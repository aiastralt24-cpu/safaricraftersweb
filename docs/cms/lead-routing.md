# Automatic enquiry assignment

In **CMS → Enquiries → Automatic enquiry assignment**, load the current rules, add a rule, choose the published form, match field/value and owner, then save. Move rules up or down to set precedence. Disable or remove rules to stop using them. This configuration requires website-wide `configure` permission for `lead`, including the existing privileged MFA policy; ordinary content-editing permission is insufficient.

Only published forms the administrator can view are offered. Product-interest and enquiry-type fields use their option labels in the editor and stable option IDs for matching. Brand routing uses a brand choice/text field; location routing can use city, state, postal-code, choice or text fields. Multi-select conditions match membership. Choice IDs match exactly; text/location values ignore case and surrounding spaces. Names, email, phone, message, consent and upload fields are excluded from routing choices.

Up to 20 ordered rules are supported. The first matching enabled rule wins. A new submission must use the same form and a matching field type in its submitted form revision. Eligible owners must have an active, unexpired membership with website-wide enquiry view permission. Eligibility is checked when saving and again during intake. If the matching owner is unavailable, intake succeeds with an unassigned enquiry and an activity entry; it does not silently fall through to another team. No match also leaves the enquiry unassigned. Disabled rules can be retained even when their form or owner is no longer available.

Assignment and its activity entry occur in the original intake transaction. The assigned enquiry starts with status `assigned` and an incremented version. Intake retries return the original receipt without rerunning routing, even after rules change or someone manually reassigns the enquiry. Configuration saves are version-checked and audited. On a conflict or uncertain save, the editor retains unsaved rules; reload explicitly to inspect the authoritative configuration. Existing enquiries are never bulk reassigned by changing these rules.

SQL **292** introduces the private configuration and service-only intake wrapper. The old intake function cannot be called directly by application roles. No live provider migration, assignment or notification has been performed. Configuration options are bounded to 200 accessible published forms and 200 eligible owners; larger catalogues fail explicitly instead of silently omitting choices. Large-catalogue search/pagination and production-scale load behaviour are not established.

Desktop/mobile browser checks cover labelled selections, ordering, save/reload, disabling, stale-save recovery, discard confirmation and denied access.
