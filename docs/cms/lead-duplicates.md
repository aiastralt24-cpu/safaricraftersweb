# Possible duplicate enquiries

Open an enquiry in **CMS → Enquiries**, then select **Check possible duplicates**. Review a match to load its latest details; unsaved changes require the existing discard confirmation. Results load in pages of 20 and reset when another enquiry opens. Errors clear the results rather than implying there are no matches.

Matching uses trimmed, case-insensitive email addresses from fields typed `email` in each submission’s pinned form revision. Current form edits do not reinterpret old answers. Text fields named “email”, names, phone numbers and notes are not identity evidence. Plus-addresses and dotted variants remain distinct. A shared address is only a possible duplicate: families and repeat customers may submit intentionally separate enquiries. Closed enquiries participate too.

SQL 290 checks current view permission on both the selected enquiry and every candidate, within one website, before pagination. Revoked memberships and inaccessible source records return no evidence. The response contains record identifiers, status, received time, version and a match reason; it omits email addresses, answers, consent and hidden-record counts. This is read-only: no records, activities, notifications or consent are merged or changed.

Local acceptance: SQL permission/revision/pagination checks, strict API response tests, and desktop/mobile browser checks cover review navigation, unsaved-change protection, missing email, malformed response and provider failure. Full suite after controlled merging: 1,693 tests pass with no skips; production build and TypeScript pass. These are local checks using synthetic records, not hosted-provider or client acceptance.

## Controlled merge

With edit access to both enquiries, choose **Compare for merge** from a duplicate result. Review either direction, compare answers, workflow fields and original consent records, then check the confirmation box and choose **Confirm enquiry merge**. Save or discard unsaved enquiry edits before starting this review.

The selected active enquiry retains its owner, status, priority, follow-up, outcome and CRM reference. The other becomes a read-only original submission, excluded from the inbox, attention queues and future duplicate candidates. The active enquiry links to retained submissions the viewer can access. No answers, consent, attribution, notes or notification jobs are copied or deleted. Original fields remain on the original record. Consent from one submission never grants permission for another.

SQL 291 requires current view and edit permission on both records (including the existing privileged MFA policy), matching pinned email evidence and both reviewed versions. It locks records in stable order, rejects self-merges, already-merged sources/targets and attempts to merge an active enquiry that already has retained submissions. This prevents chains and cycles. Multiple independent duplicate submissions can be merged into the same active enquiry after reviewing its latest version. Both versions advance and both receive an activity event. Original submissions cannot subsequently be edited or annotated; continue work on the active enquiry.

Before sending, the browser saves a minimal request identity and version pair under the actor/website scope; no answers or consent are stored there. Web Locks coordinate tabs. Storage failure blocks sending. Lost responses, refreshes and failed record reloads retain the same request for **Retry saved merge request**. Exact database retries return the recorded result without changing records or repeating events, even if the active enquiry was subsequently edited. Current access is still required. Clearing a saved retry request does not undo a merge; reload the enquiries to see their state.

Local verification covers tenant/record permissions, stale versions, permission loss, retained consent/history, queue exclusions, read-only sources, conflicting relationships and exact retries. Desktop/mobile browser checks cover both directions, explicit confirmation/cancel, unavailable storage, lost response, refresh, failed reload and navigation between the active enquiry and original submissions.
