# Direct content-reference usage

Forms, testimonials and saved pages/homepages now offer **Where this content is used** before their publication controls. Check/refresh lists visible referencing records, distinguishing current-draft references, published references and both. Results are paginated and never save or publish content. The panel resets on account/site/record/revision changes and discards aborted requests.

Migration 213 adds an authenticated, same-site reader with view checks on both the selected target and every source record. It requires the selected current revision, searches only current/published payloads for explicit `recordId` references, compares UUIDs case-insensitively, excludes self references, and returns at most 50 rows with an opaque record-ID continuation cursor. Anonymous access is denied. Hidden record counts and content bodies are not returned. The existing reference API dispatches with caller authority and private/no-store headers.

This is a read-time snapshot for direct structured references, not a complete impact graph or release authorization. It excludes URL links, global inheritance, dynamic selections, historical revisions and private previews. An empty list means no accessible matching references, not no impact. Other editors can change references after checking. Full shared CTA/global impact and provider concurrency acceptance remain pending.

Validation: all 1,413 CMS tests pass with zero skipped; production build including TypeScript passes. Local database checks cover draft-only/published-only distinctions, 52-reference pagination, stale revision, unknown target, source/target view restrictions, another website and anonymous access. Chromium confirms visible published-only usage labels and no additional draft saves inside the full MICE authoring/review flow with mocked APIs. The offline migration plan validates the 213-file sequence against a synthetic empty ledger. No provider migration was executed.
