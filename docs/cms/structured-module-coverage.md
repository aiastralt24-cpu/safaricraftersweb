Acceptance must cover the complete path:

1. A strict, versioned project contract with title, summary, body, slug/SEO, media and explicit relationship fields; incomplete drafts remain drafts.
2. A client workspace to create, search/filter, edit, preview and review the records without entering JSON or database IDs manually.
3. Current record ownership and scoped permissions, revision/conflict protection and meaningful failure recovery.
4. Trusted validation and database publication checks for referenced records, media rights, relevant claim evidence/review dates, route ownership and revision freshness.
5. Anonymous allowlisted detail/list delivery, current rights/withdrawal behaviour, SEO/sitemap integration and a rollout switch disabled by default until staging is verified.
6. Local browser and database evidence for create → edit → preview → validate → approve → publish → withdraw/restore, including stale changes and inaccessible references.
7. Hosted verification and independent client acceptance before marking the module complete.
