Products support identity/code/brand, revision-pinned category and subcategory, summaries and rich detail, benefits/features, suitable/unsuitable uses, images/videos/transcripts, specifications, editorial variants, packaging/colours/finishes, installation/precautions/warranty, geographic availability, lifecycle notes, enquiry actions, SEO and private notes. Typed reference collections cover applications, documents, projects, certifications, FAQs, related products, accessories, compatible systems and replacements. Discontinuation retains the original slug and permits explicit replacement references.

Categories contain a parent reference and ordered attribute groups. Definitions specify labels, types, numeric units, choice values, required status, not-applicable permission, display order, filter/comparison eligibility and country/region applicability. Stable attribute identities must be unique across a parent/child pair. Required regional attributes require values for each declared region. Definitions without regions are global. A subcategory must belong to the selected top-level category; recursive category nesting is not currently supported.

Specification values preserve four explicit states: known, blank, unknown and notApplicable. Known zero and false remain valid typed values. Empty known strings, nonfinite numbers and implicit string-to-number conversion are rejected. Not-applicable values need a reason and category permission. Blank/unknown do not satisfy required definitions. Variants inherit base specifications and can explicitly override them; an override cannot evade required-field checks. Category evidence must match website, language, selected identities and pinned revision. Server validation and publication load and recheck scoped category evidence; the pure validation function alone is not an authorization boundary.
