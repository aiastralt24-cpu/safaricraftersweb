# Private image previews

Migration 016 defines a private `cms-media` bucket for processed WebP derivatives. Ordinary users cannot insert, overwrite or delete objects in this bucket. Read access requires current website document-view permission and a ready inspected WebP catalog entry matching the storage key. Restrictive policies retain these checks even alongside unrelated broad policies. Editor previews may show archived or pending-rights images for management; public publication uses the separate stricter rights/availability checks.

`GET /api/cms/media/preview?site=<uuid>&asset=<id>` requires a bearer token. It resolves the catalog descriptor through the same user identity, validates the fixed `<site>/<asset>/delivery.webp` destination, then reads private storage with the user token. It bounds the response by the catalog size and checks MIME, byte count and SHA-256 before returning bytes with no-store, noindex and nosniff headers. It never fetches an original or produces a public/signed URL. Objects from older/manual catalog rows without this generated derivative layout need migration before previews work.

The media-library detail panel loads the binary endpoint with authorization, creates a temporary browser blob URL, and revokes it when the asset changes or the component unmounts. Unmounted loads are aborted; failure shows an explicit retry control. This previews the processed derivative rather than generating another thumbnail rendition. Full-grid thumbnails and dedicated small variants remain pending.

Verification: 43 local PostgreSQL tests include read scoping, write denial and membership revocation in a minimal storage model. Seven media API tests include safe descriptor resolution, bounded reads, MIME/hash failures and user-token forwarding. The actual preview component was browser-tested with a synthetic WebP fixture: load, failure, retry, decoded dimensions and blob URL use, without console warnings/errors. The temporary route and public fixture were removed. Authenticated live-provider access and end-to-end library previews remain unverified.

Deployment must apply migration 016 and configure the upload worker to write derivatives into `cms-media` while originals remain in `cms-originals`. No remote bucket or policy was changed. A preview already downloaded into an authorized browser cannot be retrospectively erased by later permission revocation; subsequent API/storage reads recheck access.
