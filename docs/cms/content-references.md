# Content reference selection service

Local migration 018 adds permission-filtered candidate search and selected-reference resolution for page, destination, journey, photo expedition, journal, specialist, testimonial, document, form, product and project records. Both functions run as the caller and retain record RLS. Search is literal, case-insensitive and limited to 200 characters with 50-record UUID cursor pages. Resolution accepts up to 100 unique IDs, retains input order and returns only an unavailable marker for missing, inaccessible, wrong-site or wrong-type records.

Results expose IDs, titles, paths, locales, review status and whether a publication pointer exists. They do not include draft payloads, author identities, revision history or storage details. Publication-pointer presence is a selection hint, not a guarantee that the referenced record can currently be delivered. The authenticated no-store `/api/cms/references` endpoint dispatches only these fixed operations using the user's token; cross-origin requests and unknown fields are rejected.

Migration 018 also adds project to the database content-type constraint, aligning it with the existing PRD composition source schema. The editor draft API accepts project records; no project publication validator is enabled by this change.

Verification: 45 database and two reference API tests passed, plus TypeScript. Coverage includes search/cursor behavior, selection ordering, wrong type/site, hidden records, anonymous access, no payload disclosure, duplicate/oversize input and cross-origin/auth rejection. Tests use PGlite's actual SQL/RLS with modeled managed auth; no remote migration has been applied. Visual selection controls, reference dependency publication checks, live resolution and staging verification remain outstanding.

The reusable visual picker is now connected to testimonials, product listings, projects and related-content section forms. It searches with pagination, resolves selected titles without fetching payloads, flags draft-only selections, prevents duplicates/over-limit choices, rechecks access before adding, and supports reorder/removal. Missing/inaccessible selections remain present with an unavailable marker until the editor removes them. Selected records can be explicitly rechecked. Listing forms expose manual/automatic mode, content type, limit and order; changing type clears old selections after confirmation.

An isolated synthetic browser fixture verified denial when access changed after search, two successful selections, disabled duplicate choices and reordering from first/second to second/first. At 390px there was no horizontal overflow or captured console warning/error. Evidence: /private/tmp/cms-reference-picker-mobile.png. Fixture removed. Eleven composition tests pass, including required manual selections for new reference sections. Listing/testimonial preview resolution, automatic-query delivery, dependency validation and authenticated staging remain pending.
